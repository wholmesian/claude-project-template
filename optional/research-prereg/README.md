# optional/research-prereg — 연구형 프로젝트용 사전등록 모듈

가설 검정·백테스트·실험처럼 **결과를 보고 기준을 바꾸면 안 되는** 프로젝트에서만 쓴다. 서비스·도구 개발 프로젝트에는 필요 없으니 `optional/`째로 지운다.

## 들어 있는 것

| 파일 | 용도 | 옮길 곳 |
|---|---|---|
| `ADR-PREREG-TEMPLATE.md` | 사전등록 ADR 양식. 가설·통계량·통과 조건·기간 분할·다중검정 보정을 **결과를 보기 전에** 고정한다 | `docs/decisions/`에 `NNNN-...md`로 복사 |
| `trial_registry.csv` | 시도 기록부(헤더만). 돌린 시도를 한 줄씩 남겨 다중검정의 분모를 잃지 않는다 | `stages/trial_registry.csv` |

## 프로토콜 요약

1. **사전등록**: 각 검정의 가설·방향·통계량·통과 조건·표본 기간을 ADR로 먼저 확정(커밋)한다. 확정 전에는 해당 계산을 시작하지 않는다.
2. **기간 분할**: 개발 구간과 holdout을 나눈다. holdout은 **승격 ADR 없이는 계산하지 않는다.** 승격할 때는 설정과 판정 기준을 동결하고 1회만 실행한다.
3. **시도 기록**: 개발 중 돌린 모든 시도(회귀 재현·스모크 포함)를 `trial_registry.csv`에 한 줄씩 남긴다. 결과가 나빠 버린 시도도 남긴다.
4. **다중검정 게이트**: 주 검정 개수를 사전에 고정하고 Holm 같은 보정 묶음을 정해 둔다. 주 검정 외의 비교는 "기술 통계" 또는 "탐색"으로 등급을 나눠 판정에 쓰지 않는다.
5. **무작위 대조**: 실제 신호는 층화한 무작위 대조(RAND)보다 나아야 한다. 대조군 설계도 사전등록한다.
6. **탐색 상한**: 개발 구간에서 시도할 수 있는 총 개수의 상한을 사전에 정하고, 올릴 때는 ADR로 한다.
7. **판정 분리**: 실행 세션은 기계적 규칙으로 범주만 붙이고, 해석·판정은 설계 세션이 보고서와 ADR로 한다.

## 사용법

1. 사용자와 위 7개 중 이 프로젝트에 필요한 것을 정한다.
2. `CLAUDE.md` 절대 규칙에 한 줄 추가한다. 예: "holdout 구간({{기간}})은 승격 ADR 없이 계산하지 않는다. 모든 시도는 `stages/trial_registry.csv`에 기록한다."
3. `ADR-PREREG-TEMPLATE.md`, `trial_registry.csv`를 옮기고 `optional/`을 지운다.

## 한계

- 이 모듈은 절차이지 통계 자체가 아니다. 보정 방법·검정력은 프로젝트마다 설계 세션이 정한다.
- 시도 기록은 자기 신고다. 빠뜨려도 도구가 막지 못한다. `fileaudit`으로 `trial_registry.csv`가 갱신됐는지는 확인할 수 있지만, 모든 시도가 기록됐는지는 확인하지 못한다.
