# reports — 사람이 읽는 보고서

단계 하나(또는 별도 대화 하나)가 끝날 때마다 보고서 1건을 쓴다. 이 프로젝트의 맥락을 전혀 모르는 사람(몇 달 뒤의 나, 새 동료, 공저자)이 읽고 이해할 수 있어야 한다.
기술 산출물(코드·JSON·parquet·그림 원본)은 `stages/<단계>/outputs/`에 두고 여기 오지 않는다. 작성 절차와 말투는 `.claude/skills/write-report`, 뼈대는 `TEMPLATE.md`.

## 규칙

- 파일명: `YYYY-MM-DD_<단계>_<제목>.md` (예: `2026-10-21_s1_데이터-이해.md`). 설계 세션의 종합은 단계 자리에 `종합`.
- 폴더는 하나(`reports/`)로 유지한다. 단계가 바뀌어도 폴더를 나누지 않는다(나누면 "어느 폴더에 쓰나" 예외가 쌓인다). 구분은 아래 목록의 `단계` 열로 한다.
- 한 번 쓴 보고서는 고치지 않는다. 틀린 곳이 나오면 새 보고서나 정정 보고서를 쓰고, 옛 보고서 맨 위에 "정정: <새 파일>" 한 줄만 붙인다.
- 보고서를 추가하면 아래 목록 **맨 아래에 한 줄 append**한다.
