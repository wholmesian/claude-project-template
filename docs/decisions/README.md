# docs/decisions — 결정 기록(ADR)

확정된 설계·데이터·작업 방식 결정을 **한 건당 한 파일**로 남긴다. 몇 달 뒤에도 "왜 이렇게 정했나"를 알 수 있게 하려는 것이다.
실험·작업 결과는 `reports/`, 현재 진행 상태는 `docs/STATUS.md`에 둔다. 결정만 여기 쓴다.

## 언제 쓰나

쓴다: 나중에 "왜?"라는 질문이 나올 선택(정의·기준·범위·도구·작업 흐름), 되돌리기 비싼 선택, 여러 대안 중 하나를 고른 선택, 이후 단계의 규칙이 되는 것, 사전등록(결과를 보기 전에 고정하는 기준).

쓰지 않는다: 오탈자·문서 정리 같은 작은 변경, 결과 자체(→ 보고서), 진행 상태(→ STATUS.md). **결과를 판정한 내용이 이후 규칙을 바꾸지 않으면 ADR이 아니라 보고서에 쓴다.**

## 규칙

- 파일명: `NNNN-짧은-제목.md`. 번호는 이어서 붙이고 **재사용하지 않는다.** 저장소가 여러 개면 번호는 저장소별이고, 다른 저장소의 ADR은 `저장소명:NNNN`으로 가리킨다.
- 작성은 `0000-TEMPLATE.md`를 복사해서 한다. 절차는 `.claude/skills/write-adr`.
- 상태: `제안` / `확정` / `확정(임시)` / `대체됨(→ NNNN)`. 사용자 확인 전에는 `제안`.
- 결정을 바꿀 때는 기존 파일을 지우지 않는다. 새 번호로 쓰고, 옛 파일의 상태를 `대체됨(→ NNNN)`으로 고치고 본문 맨 위에 한 줄 안내를 붙인다. 본문은 고치지 않는다.
- 결정을 만들고 바꾸는 것은 사용자 확인을 거쳐 **설계 세션**이 한다. 실행 세션은 읽기만 하고, 제안은 보고서의 "판단이 필요한 것"에 적는다.
- 새 결정을 추가하면 아래 목록에 **한 줄** append한다. 목록의 한 줄은 결정 문장 하나다(근거·수치·예외는 본문에).
