# ADR 작성 워크플로

결정은 **설계 세션이 사용자 확인 후** 쓴다. 실행 세션은 ADR을 쓰지 않고, 필요해 보이면 보고서의 "판단이 필요한 것"에 제안으로 적는다.

## 1. 쓸지 말지

`docs/decisions/README.md`의 "언제 쓰나"를 따른다. 요약: 나중에 "왜?"가 나올 선택, 되돌리기 비싼 선택, 이후 규칙이 되는 것, 사전등록 기준은 쓴다. 오탈자·문서 정리·결과 자체·진행 상태는 쓰지 않는다. 헷갈리면 "이 결정을 모르는 사람이 같은 실수를 반복할까?"를 묻는다.

## 2. 쓰는 순서

1. `docs/decisions/README.md` 목록에서 마지막 번호를 확인하고 다음 번호를 정한다(재사용·건너뛰기 금지).
2. 비슷한 기존 ADR이 있는지 목록에서 확인한다. 있으면 그것을 **대체**하는지 **보강**하는지 정한다.
3. `0000-TEMPLATE.md`를 `NNNN-짧은-제목.md`로 복사한다(제목은 하이픈으로 잇는다).
4. 채운다.
   - 제목은 결정 문장(동사로 끝). 결과 요약이 아니다.
   - 상태는 사용자 확인 전 `제안`, 확인 후 `확정`. 날짜는 확정일.
   - **고려한 대안**을 적는다. 대안이 없었다면 그 이유를 한 줄.
   - 정의·임계값·기간처럼 이후 바꾸면 안 되는 값은 "결정"에 값 그대로.
   - 사용자가 직접 지시·승인한 부분은 "(사용자 지시)"로 표시한다.
   - "되돌리는 조건"을 적는다.
5. 기존 ADR을 대체한다면: 새 ADR의 `대체:`에 번호를 적고, 옛 ADR의 상태를 `대체됨(→ NNNN)`으로 고치고 맨 위에 한 줄 안내를 붙인다. **옛 ADR 본문은 고치지 않는다.**
6. `docs/decisions/README.md` 목록 맨 아래에 **한 줄** append한다(결정 문장 하나).
7. 결정이 단계 규칙을 바꾸면 관련 지시서·`CLAUDE.md`·`docs/STATUS.md`를 가리키는 링크를 갱신한다(내용을 복사하지 않고 ADR 번호로 가리킨다).
8. 커밋을 만들 때(사용자 요청 시) 메시지에 ADR 번호를 적는다.

## 3. 흔한 실수

- 결과 판정을 ADR로 쓰는 것(→ 보고서). 판정이 이후 규칙을 바꿀 때만 그 규칙을 ADR로.
- 목록 한 줄에 근거와 수치를 다 넣는 것(→ 본문).
- 확정되지 않은 것을 `확정`으로 쓰는 것.
- 옛 ADR을 지우거나 본문을 고쳐 "원래 그랬던 것처럼" 만드는 것.
